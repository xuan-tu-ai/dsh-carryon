# Benchmark: CarryOn vs dsh's compaction (P3)

Milestone P3 of carrycode's `docs/design/dsh-plugin.md`: run long sessions and compare token use against
`compaction-basic` on the same tasks. This directory holds the tasks, and `scripts/bench/` holds the runners.

> [!NOTE]
> The infrastructure has been checked offline with a fake model only. No real-model numbers exist yet, so no
> claim about CarryOn's token use can be made from this repository.

## Tasks

Each task in `tasks/<id>/` has these parts:
- `task.json`: the prompt, the time limit, and an optional setup command.
- `repo/`: the starting repository the agent works in, with SPEC.md and visible tests.
- `hidden/`: the hidden tests used for grading.
- `solution/`: a reference solution. It is used only by `scripts/bench/check-tasks.mjs` to prove that the hidden
  tests can be passed.

| Task | Kind | What makes it long |
| --- | --- | --- |
| `ledger` | build from a spec | 8 requirements (accounts, posting, balances, trial balance, voids, atomic CSV import, income statement, JSON round-trip) |
| `inventory` | find and fix bugs | 8 planted deviations from SPEC.md; visible tests catch only 3, so the agent has to read and test |
| `calc` | algorithmic build | tokenizer and precedence parser with exact error positions |
| `logstats` | data-heavy CLI | a 2,600-line access log (generated by `make_log.py`), four subcommands, two output formats, exit codes |

Everything is Python 3 standard library and needs no network.

Grading (`grade.py`) copies the hidden tests into the work directory after the run, then runs them under a time
limit. **Score** is the share of hidden tests that pass. A run is **solved** when all of them pass.

Check the tasks after any edit:

```bash
node scripts/bench/check-tasks.mjs
```

A valid task fails most hidden tests before any work, and its solution passes all hidden and visible tests.

## Protocol

There are two arms, identical except for the compaction backend:

| Arm | Compaction | DSH_HOME |
| --- | --- | --- |
| `carryon` | dsh-carryon (`carryon-compaction` row) | its own, with the plugin installed |
| `basic` | dsh's `compaction-basic` | its own, no plugin |

Both arms share the following:
- the model overlay;
- `thresholdRatio` and `retainTokens` (and `headroomTokens` if given);
- the same prompt;
- a fresh git-initialized copy of the task repository.

Runs are interleaved: for each repeat and task, `carryon` runs first and then `basic`.

Each run is one headless turn. Tools are auto-approved (`--approval-policy never`) inside dsh's workspace-write
sandbox.

### Metrics (`scripts/bench/metrics.mjs`, from the session log)

- **Agent prompt / output:** the sum of `assistant/message` usage. The prompt is uncached input plus cache reads
  plus cache writes.
- **Compaction:** the usage of every `compaction/summary`, plus CarryOn's Tracker/Compiler calls in rejected folds.
  Those calls only appear in `compaction/end.error` as `[runtime usage {...}]`.
- **Cost:** computed at configurable per-million prices. The defaults are DeepSeek V4.1 Flash list prices:
  $0.15 input, $0.03 cache read, $0.60 output.
- **Peak context:** the largest prompt of a single step.
- **Counts:** CarryOn folds, other summaries (in the basic arm, or CarryOn fallbacks) and failed compactions.

### Validity

- **Contamination.** `bench/tasks` contains the hidden tests and the solutions. Output directories must therefore be
  outside this repository; the runners refuse anything else and default to the system temp directory. A run whose
  session log mentions `bench/tasks` is flagged `contaminated`, and the report lists it.
- **Silent no-compaction.** dsh computes its threshold as `min(window × thresholdRatio, window − maxTokens −
  headroomTokens)`. With its default 65,536 headroom tokens, a window under about 75k leaves no pressure budget,
  and dsh then never compacts without saying so. Pass `--headroom-tokens`. The report notes runs with no
  compaction.
- **Sample size.** Model runs vary. Use `--repeats 3` or more; the report warns below 3 runs per task and arm.

## Running

### Offline (fake model, checks the pipeline, numbers mean nothing)

```bash
node scripts/bench/run.mjs --fake --overlay scripts/bench/fake-model.patch.yml --threshold-ratio 0.5 --retain-tokens 2000 --headroom-tokens 4000 --timeout-minutes 5
```

The fake agent (`scripts/fake-messages-server.mjs --agent-steps`) runs 40 read-only `bash` steps per turn: listing,
reading files, running the tests. Tool calls therefore go through compaction in both arms, but nothing is solved.

### Real model, headless

For DeepSeek V4.1 Flash through Token Harbor, set these first:

```bash
export DEEPSEEK_BASE_URL=https://tokenharbor.ai
```

```bash
export DEEPSEEK_API_KEY=<Token Harbor key>
```

Then run:

```bash
node scripts/bench/run.mjs --overlay scripts/bench/deepseek-v41-flash.patch.yml --repeats 3
```

```bash
node scripts/bench/report.mjs <out-dir>
```

The default thresholds fold at 5% of the 1M window (about 50k tokens) and keep 4k tokens verbatim, so the tasks
compact several times. The cost has not been measured. Expect a few dollars for 24 runs (4 tasks × 2 arms × 3
repeats), but check the first run's report before starting the rest.

### Real model, Web UI

`scripts/bench/web-session.mjs` runs one long session per mode, "CarryOn mode" and dsh's "Standard mode":
1. It puts a fresh task copy in each mode's default workspace and starts `dsh web` with Playwright.
2. It sends the task prompt and then `--turns` follow-ups.
3. It grades the work directory and measures the session, writing records `report.mjs` can read, plus screenshots.

Web presets cannot be tuned from an overlay, so compaction uses the preset defaults (80% of the window). Lower the
model's `contextWindow` in the overlay to get folds in a session of reasonable length; e.g. 200000 gives a
threshold of about 126k tokens.

```bash
node scripts/bench/web-session.mjs --task ledger --turns 3 --overlay my-model-200k.patch.yml
```
